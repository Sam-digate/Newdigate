# Digate 网站设计规范（现状基线）

> 版本：v0.1  
> 日期：2026-09-02  
> 依据：`index.html`、`assets/css/*.css`、`assets/js/light-index.js`  
> 用途：后续调整 `index.html` 时的视觉、组件与交互基线。本文件描述当前页面已经形成的设计语言，并给出统一规则；不是对现有 CSS 的逐行复刻。

## 1. 产品与设计定位

Digate 被表达为一个面向复杂商业组织的 **Commerce Operating System**。页面要同时传达三件事：

1. 企业可信度：稳定、清晰、可治理，不像实验性 AI 工具。
2. 系统能力：强调数据、知识、AI Agent 三层相连，而不是孤立功能。
3. 执行感：用控制台、流程、状态、指标和输出卡片，让抽象能力显得可操作。

整体视觉关键词：**明亮、企业级、智能、系统化、精确、有轻微未来感**。

避免走向：纯装饰性赛博风、过度霓虹、过度玻璃拟态、满屏渐变、通用 SaaS 模板感。

## 3. 品牌视觉系统

### 3.1 核心色彩

| 令牌 | 当前值 | 用途 |
| --- | --- | --- |
| `--ink` | `#0F172A` | 主标题、核心文字 |
| `--ink-soft` | `#475569` | 正文、说明文字 |
| `--ink-faint` | `#94A3B8` | 元信息、辅助标签、占位文字 |
| `--violet` | `#6C47FF` | 主品牌色、主按钮、重点状态 |
| `--violet-700` | `#4F32D9` | 品牌深色、悬停与渐变终点 |
| `--blue` | `#2F6BFF` | 数据、系统、可信技术感 |
| `--blue-700` | `#2456D8` | 深蓝渐变与强调 |
| `--orange` | `#F59E0B` | Logo 中的 A、极少量暖色提示 |
| `--tint-violet` | `#F5F2FF` | 紫色浅底、图标底、标签底 |
| `--tint-blue` | `#EFF5FF` | 蓝色浅底、数据层背景 |
| `--tint-soft` | `#F6F8FC` | 交替区块背景 |
| `--paper` | `#FFFFFF` | 页面、卡片表面 |
| `--line` | `#E2E8F0` | 边框、分隔线 |

以上全局令牌统一维护在 `assets/css/tokens.css`；页面样式只允许保留有明确语义的局部覆盖。

### 3.2 品牌渐变

主渐变用于关键文字、主 CTA 和核心系统节点：

```css
linear-gradient(135deg, #3A71FF 0%, #7C3AED 100%)
```

或更偏品牌紫的版本：

```css
linear-gradient(150deg, #2C3BC0, #5733E6 55%, #7A52FF)
```

规则：

- 一个视口内只设置一个主要渐变焦点。
- 渐变文字只用于标题中的核心短语，不用于整段标题或正文。
- 橙色只做品牌签名或非常有限的信号色，不与紫色争夺主视觉。
- 大面积背景优先白色、`--tint-soft` 或极浅蓝紫，不使用高饱和满版底色。

### 3.3 深色表面

深色主要用于页脚、控制台和局部运行态界面。标准深色背景可使用 `#111827`、`#0F172A` 一带；文字使用 `#F8FAFC`，辅助文字降低到约 66%–82% 不透明度。

深色不是整站主题。它的作用是突出“系统正在运行”或在页面末尾形成收束。

## 4. 字体与排版

### 4.1 字体家族

| 角色 | 字体 | 字重 |
| --- | --- | --- |
| Display | Plus Jakarta Sans | 700–800，标题以 800 为主 |
| Body / UI | Inter | 400–600 |
| Technical label | JetBrains Mono | 500–600 |

字体均由 Google Fonts 加载。图标当前使用 Font Awesome 6.4.0。

### 4.2 标题层级

- 首页 Hero H1：`48–68px`，移动端约 `40–54px`，行高 `1.02–1.08`。
- 内页 Hero H1：`33–56px`，详情页当前为约 `42px`。
- 区块 H2：`26–42px`，行高约 `1.06–1.2`。
- 卡片 H3：常规 `16–21px`；内容详情小标题可到 `24–30px`。
- 标题字距：约 `-0.02em`；超大首页标题当前部分版本取消负字距。

### 4.3 正文层级

- Hero 引导文：`17.5–19.5px`，行高 `1.65–1.75`，长度建议不超过 `50–64ch`。
- 区块说明：`16–17px`。
- 卡片正文：`13.5–15px`。
- 元信息与标签：`10–13px`。

### 4.4 标签语言

Eyebrow、编号、运行状态、技术标签使用 JetBrains Mono、大写、`0.10–0.14em` 字距。它们承担“系统界面”的语气，不应成为长句。

## 5. 布局系统

### 5.1 容器

- 标准内容最大宽度：`1180px`。
- 正式导航统一使用 `--wrap-nav:1320px` 最大宽度、`28px` 左右 gutter，并采用 `border-box`；为新增 China / C-Digate 入口加宽，正文仍使用 `--wrap:1180px`，不再维护旧的 `1124px` 导航宽度。
- FAQ / Resources 的正文可继续使用 `1120px` 窄内容容器；它属于内容层级，不影响导航规范。
- 桌面左右内边距：`28px`。
- 小屏左右内边距：`18–22px`。
- 阅读型详情正文建议使用约 `1006px` 外容器，并给正文内容更窄的可读行长。

### 5.2 垂直节奏

建议将当前散落数值归并为以下间距标尺：

`4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 / 80 / 96 / 116`

- 首页主要区块：桌面 `96–116px`，平板约 `66–78px`，移动端约 `56–68px`。
- 内页主要区块：桌面 `74–80px`。
- Hero：根据叙事密度使用 `54–108px` 上下空间。
- 区块标题到底部内容：通常 `38–46px`。
- 卡片网格间距：`14–22px`。

### 5.3 网格

- 双栏 Hero：约 `1.02fr / .98fr` 或 `1.05fr / .95fr`。
- 常规能力卡：桌面 3–4 列，平板 2 列，手机 1 列。
- 紧凑角色/步骤卡：桌面最多 5 列，平板 2 列，手机 1 列。
- 页脚：桌面 `1.6fr 1fr 1fr 1fr`，平板 2 列，手机 1 列。

## 6. 表面、圆角与阴影

### 6.1 圆角

| 类型 | 圆角 |
| --- | --- |
| 输入框、小型控件 | `10–12px` |
| 小卡片、图标容器 | `11–16px` |
| 标准卡片 | `18–22px` |
| 大型架构窗口 / CTA | `24–28px` |
| Pill / Badge | `999px` |

圆角要与对象层级匹配。不要让所有元素都成为胶囊形；当前主导航和 CTA 按钮在不同页面存在胶囊与 `10–12px` 两套风格，建议正式统一为：导航 CTA `10–12px`，标签与筛选器才使用胶囊。

### 6.2 边框

默认使用 `1px solid var(--line)`。卡片的结构主要靠浅边框与留白建立，不依赖重阴影。

### 6.3 阴影

```css
--shadow: 0 18px 50px -24px rgba(40, 30, 90, .28);
--shadow-sm: 0 8px 24px -14px rgba(40, 30, 90, .25);
```

阴影用于悬停卡、浮动状态、架构窗口和表单。静态信息卡默认只保留边框；悬停时上移 `2–4px` 并出现阴影。

## 7. 核心组件规范

### 7.1 顶部导航

- 高度：`70px`。
- 白色半透明背景，`12–14px` blur，底部 1px 分隔线。
- Logo 视觉宽约 `102px`。
- 导航文字：Inter `14.5px / 500`。
- 当前页：品牌紫；不建议再增加重底色。
- Resources 使用下拉菜单，需支持鼠标、焦点、点击外部关闭与 Escape。
- `≤1100px` 隐藏桌面导航，显示菜单按钮和移动菜单，给新增 China / C-Digate 入口留出空间；内容网格仍按各自断点收拢。

注意：Logo 当前从 `http://www.digate.net/index_files/logo.png` 远程加载，存在混合内容与失效风险。应改成本地 HTTPS 资产，并保留文字 Logo 作为可靠回退。

### 7.2 按钮

主按钮：品牌紫或蓝紫渐变，白字，最小高度约 `44–48px`，左右内边距 `18–22px`。

次按钮：白底、浅边框、深色字；悬停时边框和文字转品牌紫。

交互规则：

- Hover：上移 `1–2px`，阴影略增强。
- Focus-visible：必须有清晰的 2–3px 外轮廓，不能只改变颜色。
- Disabled：降低透明度并取消位移与阴影。
- 图标一般置于文案右侧，使用箭头表示继续或跳转。

### 7.3 Badge / Eyebrow / Status

- Badge：白底或浅紫底、浅边框、胶囊形。
- Eyebrow：Mono、小写内容也可视觉大写，表明区块类别。
- Status：绿色表示运行正常；紫/蓝表示能力类别；橙色只用于谨慎的提示或品牌点睛。

### 7.4 信息卡片

标准结构：图标或标签 → 标题 → 说明 → 可选状态/数据/链接。

- 默认白底、浅边框、`18px` 左右圆角。
- 内边距通常 `22–30px`。
- 卡片内不堆叠超过两种强调色。
- 同一网格内卡片高度与底部动作区域应对齐。

### 7.5 系统架构与工作台视觉

这是品牌最有辨识度的组件族，应优先保留：

- 窗口标题栏、运行状态、数据源、三层架构、输出节点。
- 数据基础层偏蓝；知识层偏紫；Agent 执行层使用更强的紫色或渐变。
- 连接关系用线、箭头、轨道或轻动效表达。
- 文案必须是真实的产品语义，例如数据同步、Agent 计划、内容生成、审批与结果，而非装饰性随机数据。
- 移动端将横向流程改为纵向；隐藏非关键连接线，保留顺序和标签。

### 7.6 Accordion / FAQ

- 整行可点击，不只让加号可点击。
- 标题、展开标记和内容保持稳定对齐。
- 同组默认只展开一项；FAQ 可按内容需要允许多项。
- 使用 `aria-expanded`，展开内容必须保持键盘可达。

### 7.7 表单

- 输入框高约 `44–48px`，圆角 `11px`，1px 浅边框。
- Focus 使用品牌紫边框加外轮廓。
- 标签使用 `12.5px / 500`，不可只依赖 placeholder。
- 必填、错误、成功与提交中状态需要完整定义。
- Demo 页当前是视觉表单卡，但字段未包在真正的 `<form>` 提交流程中；后续产品化时必须补齐语义和反馈。

### 7.8 页脚

内容型页面目前趋向深色页脚，适合作为全站统一方向：`#111827` 背景、白色 Logo、四列链接和底部法律/信任信息。

## 8. 图像与图标

- 图标使用 Font Awesome 的线性/实心图标，单个卡片只使用一个主图标。
- 产品和系统关系优先用 HTML/CSS/SVG 几何与可信图标表达。
- 客户案例、团队、文章使用真实图片；统一裁切比例与 `object-fit: cover`。
- 图片必须有有意义的 `alt`；纯装饰复制图应使用空 `alt` 和 `aria-hidden="true"`。
- 当前图片依赖多个外部域名（`agent.xdigate.cn`、`up2china.com`、`digate.ai`、Unsplash 等）。正式发布前应本地化关键资产，统一压缩、尺寸和缓存策略。

## 9. 动效与交互

当前动效语言包括：

- 卡片悬停上移 `2–4px`。
- 滚动进入时淡入并上移约 `22–28px`。
- 品牌渐变缓慢流动。
- 架构连线、Agent 运行、内容生成与审批过程的循环演示。
- 搜索、筛选、分页、下拉菜单、移动菜单、Accordion 和详情数据替换。

规范：

- 微交互 `160–220ms`；区块进入 `600–720ms`。
- Company 内容区块沿用 Use Cases 的首次滚入效果：距离视口底部约 `90px` 时触发，`720ms` 淡入、上移 `28px`，模糊从 `2px` 渐清；已显示内容不重复隐藏。Hero 和导航直接显示，未启用脚本或开启减少动态效果时内容保持可见。
- 优先使用 `transform` 与 `opacity`，避免布局抖动。
- 循环演示不能妨碍阅读；重要信息不能只依赖动画出现。
- 全部动效必须尊重 `prefers-reduced-motion: reduce`。
- 页面切换后应回到顶部并更新清晰的当前导航状态。

## 10. 响应式规则

当前主要断点集中在：

- `1100px`：复杂架构、双引擎和大型复合布局开始堆叠。
- `980px`：多栏内容降为 1–2 列；全站导航因新增入口已提前至 `1100px` 收起。
- `640px` / `680px`：Hero、按钮组、复杂流程、内容卡进一步单列化。
- `560px`：传统卡片网格、表单双列、页脚完全单列。

后续统一建议只保留四个语义断点：

```text
Desktop wide: > 1100
Desktop / tablet landscape: 981–1100
Tablet / mobile landscape: 641–980
Mobile: <= 640
```

移动端优先级：标题与 CTA → 核心能力 → 证明内容。复杂装饰、重复状态和连接线可以降级，但不能破坏信息顺序。

## 11. 内容与语气

文案语气应是：简洁、自信、系统化、以业务结果为导向。

推荐结构：

1. 先说业务变化或结果。
2. 再解释数据、知识、Agent 如何连接。
3. 最后给出下一步动作。

避免：空泛的 AI 口号、连续多个形容词、同一页反复解释同一句“连接数据与 AI”。卡片标题尽量控制在一行或两行，正文控制在 2–4 行。

## 12. 可访问性基线

- 所有交互控件必须有键盘操作和可见焦点。
- 菜单、Accordion、筛选器和详情卡需维持正确的 ARIA 状态。
- 正文与背景对比至少满足 WCAG AA。
- 不使用颜色作为唯一状态信号；状态应同时有文字或图标。
- 触控目标建议不小于 `44 × 44px`。
- 页面切换后应管理焦点；当前 radio 驱动的视觉切页不会自动完成这一点。
- 同一 DOM 中必须保证 `id` 唯一。

## 13. 当前实现风险与治理规则

以下是继续调整前需要明确的现状：

1. **样式覆盖仍然偏重**：第一轮安全清理已删除未引用的 `light-index.combined.css`（约 263 KB）、去除 22 条完全重复规则，并让每个页面只加载自身 CSS；当前 `overrides.css` 仍约 348 KB，活动 CSS 中还有约 1236 个 `!important`。后续应按组件逐批收敛，不能盲目批量删除。
2. **全局令牌（已处理）**：颜色、字体、1180px 标准容器、1120px 窄容器、1006px 阅读容器、页面边距、圆角和阴影已集中到 `assets/css/tokens.css`；页面只保留 FAQ 宽度与 Blogs 辅助色等明确特例。
3. **组件重复**：导航、按钮、CTA、页脚在多个页面分别定义，且按钮圆角、导航定位、页脚明暗已有分叉。
4. **断点碎片化**：`560 / 640 / 680 / 980 / 1100` 混用，后续新增样式应先使用本规范的四档断点。
5. **重复 ID（已处理）**：案例详情的默认内容与三个模板都已使用案例命名空间，例如 `market-potential-results`、`luxury-beauty-background`；全部活动 HTML 已通过单文件 ID 唯一性检查。
6. **编码约束（已处理）**：活动 HTML、CSS、JS 已确认是合法 UTF-8；实际写入源码的 `360掳` 已修复为 `360°`，并通过 `.editorconfig` 固定后续文本文件使用 UTF-8。终端若再次显示 `鈥?`、`鈻?`，应先检查读取命令的编码参数，避免把显示层误判为源文件乱码。
7. **外部资产风险**：Logo 使用 HTTP，关键图片跨多个外部域；应本地化核心品牌资产。
8. **页面拆分（已处理）**：原约 214 KB、包含 13 个页面状态的 `index.html` 已拆为 13 个独立 HTML 文件；首页现约 32 KB。后续仍可继续提取共享导航与页脚模板，减少跨文件重复。
9. **非产品 UI**：顶部页面切换 `.bar` 是演示工具，不应进入正式站点。

后续新增或修改样式时遵循：

- 优先改全局令牌与共享组件。
- 页面特例必须限定在页面根节点内，但不复制整套基础规则。
- 禁止为解决普通优先级问题新增 `!important`；先清理选择器与加载顺序。
- 同类组件只保留一个正式版本，旧版本确认无引用后再删除。
